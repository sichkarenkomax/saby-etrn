# SABY ЭТрН — документация

Интеграция электронных транспортных накладных (ЭТрН) между СБИС (online.sbis.ru) и Bitrix24 (коробка) через смарт-процесс «ЭТрН».

> **Важно.** Это не массовый продукт, а разработка под задачи конкретного предприятия. Гарантий совместимости с другими конфигурациями нет. Если возникнут проблемы — решаются самостоятельно: исходный код открыт, документация описывает устройство настолько, чтобы с ним можно было разбираться.

---

## 1. Что делает приложение

- Показывает статусы ЭТрН из СБИС прямо в Bitrix24 (вкладка «SABY → Bitrix24»).
- Сопоставляет ЭТрН из СБИС с карточками смарт-процесса «ЭТрН» в Б24 по паре ИНН (отправитель + получатель) и заполняет карточки из титульных данных накладной.
- Автосинхронизация по расписанию (внешний cron): обновляет статусы привязанных карточек, находит несопоставленные ЭТрН.
- Уведомляет ответственного в Б24: о несопоставленных ЭТрН, об ошибках синхронизации, об отвале авторизации SABY.
- Позволяет создавать ЭТрН в СБИС из бизнес-процесса Б24 (активити «SABY: создать ЭТрН»): черновик создаётся по данным карточки — обязательный реквизит только ИНН получателя, остальное заполняется тем, что есть.

## 2. Состав

| Компонент | Где | Назначение |
|---|---|---|
| Embedded-приложение | `https://<портал>/local/saby-etrn/public/index.php` | интерфейс в iframe Б24 |
| api.php | `public/api.php` | REST приложения (данные, настройки, журнал) |
| cron_sync.php | `public/cron_sync.php` | автосинхронизация по расписанию (зовётся cron'ом по секрету) |
| activity.php | `public/activity.php` | обработчик активити бизнес-процесса (создание ЭТрН в SABY) |
| storage/ | на сервере | settings.json (настройки), saby_token.json (общая сессия SABY), saby_creds.json (логин/пароль для авто-релогина), saby_member_ids.json (кэш ID участников ЭДО), app.log (журнал), cron_secret.txt (секрет cron-URL) |

Требования: PHP 8.x, Bitrix24 (коробка), аккаунт СБИС с доступом к ЭДО, внешний cron на сервере с возможностью запускать curl/wget по HTTPS.

## 3. Установка

1. Разместить код приложения на сервере Б24 в `/local/saby-etrn/` (или другом каталоге — путь не фиксирован).
2. В админке Б24: **Приложения → Разработчикам → добавьте локальное приложение** с правами: CRM, Пользователи, Служба сообщений, Бизнес-процессы, Чат и уведомления, Учет рабочего времени. URL приложения — путь до `public/index.php`. После установки приложение появится в меню Б24.
3. Создать **входящий вебхук** (Приложения → Разработчикам → Готовые сценарии → Другое → Входящий вебхук) с теми же правами. Важно: если позже менять права у существующего вебхука, коробка может не применить их к токену (методы будут отвечать `insufficient_scope`) — тогда вебхук нужно пересоздать, а новый URL вставить в настройках приложения (см. ниже).

### Первичная настройка (вкладка «Подключение»)

1. **SABY**: ввести логин/пароль сотрудника СБИС, под которым работает интеграция. Отметить галку «запомнить» — тогда сохранённые креды позволят cron'у самовосстанавливаться после сброса сессии. Все остальные сотрудники используют это подключение автоматически, без своего логина/пароля (личная авторизация тоже возможна и имеет приоритет, но не обязательна). Вся работа в СБИС идёт от имени этой учётки.
2. **Смарт-процесс**: выбрать «ЭТрН» из списка. Список грузится серверно через вебхук, поэтому права пользователя Б24 на смарт-процессы не нужны.
3. **Настройки → Автосинхронизация**: включить, задать интервал (5–1440 мин), при необходимости заменить вебхук (поле видно только администраторам).
4. **Настройки → Уведомления**: выбрать ответственного, отметить типы уведомлений (несопоставленные / ошибки / отвал авторизации), опционально «только в рабочее время» (проверяется по timeman ответственного).
5. **Настройки → CRON**: установить cron-задачу (кнопка показывает готовую команду). Периодичность cron — чаще интервала синхронизации (например, каждые 5 минут): cron просыпается, проверяет, истёк ли интервал, и делает работу только когда пора.
6. **Бизнес-процесс**: для создания ЭТрН из БП зарегистрируйте активити «SABY: создать ЭТрН» в бизнес-процессе (CODE `saby_etrn-create`, обработчик — URL `public/activity.php`). На текущем портале активити уже зарегистрировано; при установке на другом портале регистрацию нужно выполнить заново. При изменении состава параметров активити требуется перерегистрация.

## 4. Использование

- **Вкладка «SABY → Bitrix24» (ЭТрН)**: список ЭТрН из СБИС со статусами (фаза перевозки — состояние документа).
- **Сопоставление ЭТрН**: автоматические пары (по ИНН-паре) показываются сверху, несопоставленные — снизу с кнопкой «Создать карточку в Б24» и галкой «Не уведомлять об этой ЭТрН» (серверная настройка, действует мгновенно).
- **Карточка ЭТрН в Б24**: поля СABY ID, номер, статус, ссылка на кабинет СБИС и титульные данные (перевозчик, получатель, водитель, груз, вес/объём, адреса) заполняются из титула при сопоставлении. `ufCrm19SyncStatus = done` — документ завершён в СБИС (код состояния 7).
- **Диагностика**: журнал синхронизации (новые сверху), фильтр по каналам (пропуски по интервалу / синхронизация / активити / уведомления — сохраняются сразу при клике), лимит размера файла журнала (при превышении — ротация).

Статусы документов СБИС в поле «Статус документа в SABY»: фаза + состояние, например «Выдача груза — Выполнение завершено успешно». Коды состояний: 0 — редактируется, 3 — отправлен, 4 — доставлен, 7 — завершён успешно, 9 — завершён с проблемами, 19/20/22 — отозван/удалён/аннулирован и др.

## 5. Технические нюансы

**Сессии SABY.** СБИС сбрасывает сессии; cron при сбросе делает авто-релогин из `storage/saby_creds.json` (права 600, только пользователь bitrix). Если кредов нет — приложение попросит авторизоваться заново и пришлёт уведомление «авторизация SABY отвалилась» (если включено).

**Вебхук Б24.** Один вебхук используется для: списка смарт-процессов, уведомлений (`im.notify`), проверки рабочего времени (`timeman.status`), чтения карточек и реквизитов. Нужные права: crm, im, timeman (user — не обязательно: список сотрудников идёт через BX24 изнутри iframe). Признак неправильных прав: в журнале `The request requires higher privileges` — пересоздать вебхук (не редактировать!) и вставить новый URL в настройках.

**Несопоставленные.** В уведомления попадают только ЭТрН без карточки, при этом завершённые/аннулированные старше суток исключаются (карточка им уже не нужна). Список в интерфейсе и список в уведомлении используют одинаковую логику отсева.

**Анти-спам уведомлений.** О несопоставленных — только при изменении списка (хэш). Об ошибках синхронизации и об отвале авторизации — на каждый неудачный прогон (при длительной проблеме будут повторяться).

**Создание ЭТрН из БП.** Активити синхронное: POST в `activity.php` → СБИС.ЗаписатьДокумент (формализованный титул ЭТрН, XML, cp1251). Перевозчик определяется идентификаторами участников ЭДО в ИдФайл (порядок: перевозчик → отправитель → получатель); ID участников кэшируются в `saby_member_ids.json`. Обязателен КПП получателя и ВидТар=«8A». ВнешнийИдентификатор генерируется от времени — повторный запуск БП создаёт новый черновик (идемпотентность не гарантируется).

**Права файлов.** `storage/*.json` — 600, владелец bitrix. Пользователь `hermes` (или любой не-bitrix) эти файлы не читает — это нормально.

**Оп cache.** Коробка может отдавать старую версию PHP-файла после деплоя (md5 совпадает, mtime нет). Лечение: touch файла или `opcache_reset()` через временный скрипт.

**Журнал.** `storage/app.log`, ротация по лимиту (1–50 Мб). Фильтр каналов применяется при записи — отключённая категория вообще не пишется; уже записанные строки не удаляются.

**Безопасность.** Секреты (вебхук, креды SABY, cron-секрет) хранятся только в `storage/` и через API не отдаются (вебхук маскируется значением `***set***`). Публичные скрипты без авторизации запрещены; cron-URL защищён секретом. При обновлении не оставляйте в `public/` временных диагностических скриптов.

## 6. Диагностика проблем

| Симптом | Причина / лечение |
|---|---|
| `insufficient_scope` в журнале | У вебхука фактически нет нужных прав → пересоздать вебхук, вставить URL в настройках |
| «SABY не подключён» у сотрудника | Нет общей сессии: авторизоваться под любой учёткой с галкой «запомнить» (или проверить, что `saby_token.json` не пуст) |
| «Рабочий день не начат» при открытом дне | Проверить право timeman у вебхука и статус timeman ответственного (OPEN/OPENED, CLOSED, PAUSED) |
| `ACCESS_DENIED` при выборе смарт-процесса | Не должно появляться (список идёт через вебхук); если появилось — обновить `app.js`/`api.php` |
| Уведомления не приходят | Проверить: ответственный задан, галка типа включена, право im у вебхука, `im.notify` в журнале |
| Вкладки не переключаются | Ошибка JS (обычно null-элемент после правки вёрстки) — консоль браузера (F12) |
| Cron молчит | Проверить crontab и секрет в URL; в журнале — «Пропуск: интервал не истёк» значит cron жив, просто ждёт интервал |

При любых правках: `php -l` для PHP, `node --check` для JS перед выкладкой; файлы на прод обновлять пофайлово и сверять md5.


### Привязка к нашей организации (что заменить при развёртывании)

Код изначально писался под конкретное предприятие, поэтому реквизиты «нашей организации» зашиты в код. В этом экспорте они заменены заглушками — при развёртывании заполни своими значениями:

| Файл | Что заменить | Значение-заглушка |
|---|---|---|
| `includes/config.php` | `OUR_INN` | `'0000000000'` — ИНН организации |
| `includes/config.php` | `OUR_KPP` | `'000000000'` — КПП организации |
| `includes/config.php` | `OUR_NAME_SHORT` | краткое наименование («ООО "…"») |
| `includes/config.php` | `OUR_NAME_FULL` | полное наименование (идёт в титул ЭТрН) |
| `assets/js/match.js` | `const OUR_INN = '0000000000'` | тот же ИНН (JS-копия для поиска компаний) |

Где используются:

1. **Определение партнёра**: в ЭТрН из СБИС есть наша организация и контрагент; кто из двух «мы», определяется по `OUR_INN` (`public/api.php`, `public/cron_sync.php`, `assets/js/match.js`).
2. **Сопоставление**: компании подбираются по ИНН — наша организация всегда `OUR_INN`, направление («Входящий/Исходящий») определяет sender/receiver (`assets/js/match.js`).
3. **Создание ЭТрН в СБИС** (`includes/saby_create.php`, `includes/etrn_title.php`): отправитель титула — наша организация (`OUR_INN`, `OUR_KPP`, оба наименования), идентификатор участника ЭДО ищется в СБИС по ИНН+КПП.

Без замены заглушек сопоставление и создание ЭТрН работать не будут (ИНН 0000000000 не найдётся ни в СБИС, ни в Б24). Проверка после замены: `grep -rn "0000000000\|ОРГАНИЗАЦИЯ" includes/ assets/js/` не должен находить заглушек.

## 7. Смарт-процесс: поля и сопоставление

Смарт-процесс на стороне пользователя может называться как угодно — приложение не привязывается к названию, он выбирается из списка в настройках (определяется по entityTypeId). Привязка идёт к **кодам пользовательских полей**: приложение ищет поля по точным кодам, перечисленным ниже. Названия полей (заголовки) — любые удобные.

### Обязательные поля (без них сопоставление не работает)

| Код поля | Тип в Б24 | Название (рекомендация) | Откуда заполняется |
|---|---|---|---|
| `ufCrm19SabyId` | Строка | ID документа SABY | идентификатор ЭТрН в СБИС (ключ синхронизации) |
| `ufCrm19Sender` | Привязка к CRM-сущности (Компания) | Отправитель | компания отправителя (по ИНН-паре) |
| `ufCrm19Recepient` | Привязка к CRM-сущности (Компания) | Получатель | компания получателя (по ИНН-паре) |

### Поля статусов (заполняются синхронизацией)

| Код поля | Тип | Название | Содержимое |
|---|---|---|---|
| `ufCrm19SabyNumber` | Строка | Номер ЭТрН в SABY | номер накладной в СБИС |
| `ufCrm19SabyStatus` | Строка | Статус документа в SABY | «фаза — состояние» (см. раздел 4) |
| `ufCrm19SabyUrl` | Строка | Ссылка на документ в SABY | прямая ссылка на ЭТрН в кабинете СБИС |
| `ufCrm19SyncStatus` | Строка | Статус синхронизации | `auto` — привязана; `done` — завершена в СБИС (код 7) |
| `ufCrm19SyncDate` | Дата | Дата последней синхронизации | время последнего обновления |

### Поля титула (заполняются из ЭТрН при сопоставлении)

| Код поля | Тип | Название | Источник в титуле ЭТрН |
|---|---|---|---|
| `ufCrm19TransportCompany` | Привязка к CRM (Компания) | Перевозчик | компания перевозчика, найденная по ИНН в Б24 |
| `ufCrm19ManagerPhone` | Строка | Телефон менеджера перевозчика | телефон перевозчика из титула |
| `ufCrm19DriverName` | Строка | ФИО водителя | водитель |
| `ufCrm19DriverPhone` | Строка | Телефон водителя | телефон водителя |
| `ufCrm19Dep` | Адрес | Место отправления | пункт погрузки |
| `ufCrm19Dest` | Адрес | Место назначения | пункт разгрузки |
| `ufCrm19Goods` | Строка | Товары | наименование груза |
| `ufCrm19Weight` | Число (double) | Масса, кг | масса груза |
| `ufCrm19Size` | Число (double) | Объем, м. куб. | объём груза |
| `ufCrm19Qantity` | Целое число | Количество мест | количество грузовых мест |
| `ufCrm19Comment` | Строка | Комментарий | реквизиты перевозчика, если его нет в Б24 («Перевозчик из ЭТрН (нет в Б24): …») |

### Дополнительные поля (используются, но не критичны)

| Код поля | Тип | Название | Примечание |
|---|---|---|---|
| `ufCrm19SabyAttachmentId` | Строка | ID вложения SABY | резерв |
| `ufCrm19SabyError` | Строка | Ошибки в SABY | текст последней ошибки создания в SABY |

### Правила сопоставления

1. Карточка ↔ ЭТрН связываются по `ufCrm19SabyId`. Карточки без этого поля считаются свободными кандидатами.
2. Автопара строится по совпадению пары ИНН: `ufCrm19Sender` + `ufCrm19Recepient` (ИНН берутся из реквизитов компаний) против пары ИНН в ЭТрН (отправитель/получатель с учётом направления «Входящий/Исходящий»).
3. Если кандидат ровно один — автопривязка. Если ни одного — ЭТрН попадает в «Несопоставленные» (кнопка «Создать карточку в Б24» создаёт карточку и ищет компании по ИНН, не создавая новых). Если кандидатов несколько — тоже «Несопоставленные» с выбором вручную.
4. При каждом прогоне синхронизации обновляются: статус в SABY, статус синхронизации, дата. Титульные поля можно дотянуть кнопкой «Обновить из SABY» / «Обновить все».
5. Коды полей зашиты в коде приложения (`assets/js/match.js`, массив `TITLE_FIELDS`, константа `ADDRESS_FIELDS`). Если нужен другой префикс (например, у нового смарт-процесса Б24 сгенерировал `ufCrm1072*`) — правится в `match.js` (константы и объекты fields) и `assets/js/sync.js`.

## 8. Экспорт и размещение

Исходники экспортируются прямо из git-репозитория (архив не содержит `storage/` — секретов и данных нет):

```bash
git archive --format=tar.gz --prefix=saby-etrn/ HEAD -o saby-etrn-src.tar.gz
git archive --format=zip   --prefix=saby-etrn/ HEAD -o saby-etrn-src.zip
```

- `--prefix=saby-etrn/` — чтобы при распаковке получился каталог `saby-etrn/`.
- В архив попадает всё, что закоммичено: код, вёрстка, `DOCS.md`. Локальные логи, `storage/`, `vendor/` исключаются (`*.log`, `.gitignore`).
- Перед передачей проверьте архив на отсутствие секретов: `grep -rniE "rest/[0-9]|password" saby-etrn` должен не находить ничего, кроме служебных упоминаний (ИНН организации в конфиге — публичный реквизит, не секрет).
- Для развёртывания из архива: распаковать в `/local/saby-etrn/` на сервере Б24 и следовать разделу 3.

Готовые архивы последней версии: `/tmp/export/saby-etrn-src.tar.gz` (66 Кб) и `/tmp/export/saby-etrn-src.zip` (88 Кб).
